# 한눈애 — 순수 HTML 웹

관계 취향을 정리하는 8개 문답, 동의 후 초대·비교 링크, 32개 대화카드를 제공하는 순수 HTML·CSS·일반 JavaScript로 동작하는 정적 웹앱입니다.

## 제품 범위

- **오늘:** 문답 시작/이어하기, 오늘의 대화, 이용 안내
- **마음문답:** 8개 질문, 답변 수정, 진행 유지, 관계 카드
- **둘이 비교:** 링크를 직접 나눠 두 사람의 같은 답·다른 답과 대화 질문 확인
- **대화카드:** 4개 주제, 32개 질문, 무작위 질문, 즐겨찾기, 문구 복사
- **설정:** JSON 백업, 형식 검증 복원, 전체 삭제, 저장·공유 안내

처음부터 동작하는 개인 도구입니다. 실제 회원을 모집하거나 낯선 상대를 추천하지 않습니다. 이름·전화번호·이메일·위치를 요구하지 않습니다. 심리 진단이나 궁합 점수를 제공하지 않습니다.

## 파일

| 파일 | 역할 |
|---|---|
| index.html | 앱 구조, 내비게이션, 확인 대화상자 |
| style.css | 데스크톱/모바일 레이아웃, 읽기 쉬운 색·글자, 포커스 표시 |
| app.js | 화면, 로컬 저장, 링크 공유, 백업·복원·삭제 |
| core.js | 질문·대화카드, 데이터 검증, 링크 인코딩·해석, 답변 비교 |
| manifest.webmanifest / pwa.js / sw.js | 홈 화면 설치 정보·상대 경로 서비스워커·오프라인 앱 파일 캐시 |
| scripts/check.cjs | Node.js 기본 모듈만 사용하는 배포 파일·핵심 기능 검증 |
| native-bridge.js | Android의 파일 저장·공유·인쇄 메시지 연결, 일반 브라우저 폴백 |
| common-account.js / common-account.css | 중앙 한눈 계정 연결·장애 시 계정 웹 링크·네이티브 광고 식별 |
| .github/workflows/pages.yml | 빌드 없이 앱 파일만 GitHub Pages에 배포 |
| .nojekyll | GitHub Pages에서 정적 파일을 그대로 제공 |

HTML에서 `core.js → native-bridge.js → app.js → common-account.js → pwa.js`를 일반 `defer` 스크립트로 순서대로 읽습니다. `core.js`는 `window.HannunaeCore` 하나만 공개하며, 앱 내부 상태는 IIFE 안에 둡니다. React·Next.js·Vite·npm 설치·컴파일·애플리케이션 ES module이 필요 없습니다. 한눈 공통 계정 연결에만 중앙 운영 모듈을 불러옵니다.

## 로컬 실행과 배포

저장소 루트에서 실행합니다.

```sh
python -m http.server 8080 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8080/`를 엽니다. 별도 빌드 출력 디렉터리가 없으므로 **저장소 루트 자체**를 정적 호스팅 대상으로 사용합니다. `file://`에서도 스크립트는 ESM 제약 없이 로드되지만, 저장소·복사·서비스워커의 브라우저별 동작이 달라 실제 실행과 검증은 HTTP(S)를 사용합니다.

GitHub Pages의 게시 소스는 **GitHub Actions**로 지정합니다. `.github/workflows/pages.yml`이 `main` 푸시 또는 수동 실행 시 검증 후 HTML·CSS·JS·manifest·아이콘만 선별 복사하여 배포합니다. npm 설치·컴파일은 없으며 README·검증 스크립트·GitHub 설정 파일은 배포 산출물에서 제외합니다. 업로드 산출물 보관 기간은 1일입니다. 앱 코드·아이콘·manifest·서비스워커 경로가 모두 `./` 기준이어서 `/hannunae-web/` 같은 하위 경로에서도 실행됩니다. 외부 웹 서버를 써도 같은 파일을 제공하면 됩니다. HTTPS 또는 로컬 보안 컨텍스트에서 서비스워커가 설치되며, 한 번 읽은 앱 파일은 오프라인에서 다시 열 수 있습니다. 캐시 이름에 배포 경로를 포함하여 다른 경로의 배포와 캐시가 충돌하지 않게 합니다.

호스팅 주소가 달라지면 브라우저 저장 공간도 달라집니다. 기존 배포에서 받은 JSON 백업을 새 주소에서 복원해야 합니다. Android WebView와 일반 브라우저 사이에도 자동 기록 동기화가 없습니다.

## 저장 동작

- 키: hannunae.maeum.v1
- 저장 데이터: 문답 답변, 현재 질문, 즐겨찾는 카드 ID, 최근 변경 날짜
- 상대의 답변은 열린 링크에서만 읽고 로컬 저장·백업에 포함하지 않습니다.
- 브라우저 삭제·시크릿 모드 종료·기기 변경에 대비해 JSON 백업을 제공합니다.
- JSON 파일과 브라우저 저장은 암호화되지 않습니다. 앱 잠금·계정 동기화 기능은 없습니다.
- 잘못된 기존 저장 데이터는 자동으로 덮어쓰지 않고 저장 잠금 상태로 시작합니다. 사용자는 유효한 백업을 복원하거나 전체 삭제할 수 있습니다.
- 저장 공간 부족·권한 거부 시 현재 탭에서 임시 사용하며, 지속 경고와 백업 안내를 표시합니다.
- 다른 탭에서 같은 키가 변경되거나 전체 삭제되면 현재 탭의 쓰기를 멈춥니다. 백업 후 새로고침을 안내하여 오래된 상태의 덮어쓰기를 막습니다.

## 동의와 공유

1. 문답을 모두 마친 뒤 둘이 비교 화면에서 공유 범위를 읽습니다.
2. 체크박스로 동의해야 링크 생성 버튼이 활성화됩니다.
3. 초대 링크의 #invite= 뒤에 초대한 사람의 8개 답변만 들어갑니다.
4. 상대가 문답을 완료하면 두 사람의 답변과 대화 질문을 볼 수 있습니다.
5. 상대가 동의하여 만든 #compare= 링크에는 양쪽의 8개 답변이 들어갑니다.
6. 초대자는 받은 비교 링크를 열어 결과를 볼 수 있습니다. 기존 문답을 덮어쓰지 않습니다.

초대 데이터는 일반 웹 요청의 서버 경로·쿼리에 들어가지 않지만, 링크를 가진 누구나 읽을 수 있습니다. 메신저와 방문 기록에 남을 수 있고 발행 후 취소할 수 없습니다. 앱은 사용자의 직접 복사·시스템 공유 동작 없이 메시지를 발송하지 않습니다. 공개 동의 체크를 해제하면 생성된 링크 표시와 공유 동작을 비활성화합니다.

배포 사이트의 접근 권한은 호스팅 설정을 따릅니다. 비공개 배포이면 상대방도 사이트 접근 권한이 필요합니다.

## 수동 검증 절차

| 항목 | 순서 | 예상 결과 |
|---|---|---|
| 첫 방문 | 브라우저 저장을 비운 뒤 열기 | 실제 문답 시작 버튼, 완료/회원 수를 꾸미지 않은 홈 |
| 문답 재개 | 3개 답변 후 새로고침 | 같은 브라우저에서 답변 유지, 이어하기 가능 |
| 관계 카드 | 8개 답변 완료 | 실제 선택한 답 8개, 진단·궁합 점수 없음 |
| 답변 수정 | 관계 카드의 수정 버튼 | 해당 질문 진입, 수정 후 결과에 반영 |
| 초대 동의 | 동의 전/후 링크 버튼 비교 | 동의 전 비활성, 이후 링크 생성 |
| 초대 수신 | 생성된 링크를 새 브라우저 컨텍스트에 열기 | 상대 답변을 먼저 드러내지 않고 내 문답 시작 |
| 비교 반환 | 응답자 문답→동의→비교 링크 생성→초대자에서 열기 | 양쪽 답변 8개 정확히 표시, 원래 내 기록 유지 |
| 링크 형식 검증 | 잘못된 base64, 범위 밖 답변, 필드 추가, 과도하게 긴 링크 | 안내 메시지, 앱 계속 사용 가능 |
| 즐겨찾기 | 카드 하트 클릭 후 새로고침 | 저장 목록 유지, 취소 가능 |
| 무작위 질문 | 주제 필터 후 질문 뽑기 | 선택한 주제/저장 목록 안에서 선택 |
| 백업/복원 | JSON 내보내기→삭제→가져오기→확인 | 문답·즐겨찾기 복구, 상대 답변 없음 |
| 잘못된 복원 | 다른 앱 파일, 잘못된 JSON, 100KB 초과 | 기존 데이터 변경 없이 거부 안내 |
| 저장 실패 | localStorage 쓰기가 실패하는 브라우저 | 지속 경고, 저장 성공을 주장하지 않는 임시 보관 안내 |
| 깨진 저장 | 저장 키에 잘못된 JSON 삽입 후 열기 | 자동 덮어쓰기 없음, 복원/초기화 가능 |
| 다중 탭 | 다른 탭에서 답변 수정 또는 전체 삭제 | 현재 탭 쓰기 잠금과 새로고침 안내 |
| 전체 삭제 | 삭제 버튼→취소/확인 각각 | 취소 시 유지, 확인 시 저장·현재 초대 제거 |
| 키보드 | Tab, Shift+Tab, 방향키, Enter, Escape | 라디오 선택·포커스·확인창 동작, 초대 링크 유지 |
| 화면 폭 | 360/390/768/1440px에서 확인 | 가로 넘침 없이 핵심 기능 사용 |
| 접근성 | 확대, reduced-motion | 읽기 가능한 안내, 감속 동작, 필수 기능 식별 |

## 자동 검증

```sh
node scripts/check.cjs
```

설치할 npm 패키지가 없습니다. 일반 스크립트 구문, 참조 파일·manifest·오프라인 캐시 파일, 초대/비교 링크 왕복, 잘못된 링크 거부, JSON 백업 왕복, 문답 재개 상태를 검증합니다. 브라우저의 사용자 흐름은 위 수동 검증 표를 따릅니다.

## 현재 제외된 범위

이 웹 저장소에는 결제·구독·이메일·푸시 알림·계정 동기화·실제 회원 매칭·상담 기능이 없습니다. Android 네이티브 앱의 코드와 빌드는 별도 저장소에서 관리합니다.

## 한눈 서비스 공통 적용 범위

| 구분 | 동작 |
| --- | --- |
| 공통 계정 | 중앙 한눈 계정의 사이트 식별자 `hannunae`와 `#siteAccountSlot`을 사용합니다. 임의의 새 회원 시스템은 만들지 않습니다. |
| 기록 보관 | 답변·시·편지·마음 기록은 로컬에 보관합니다. 한눈 계정 로그인은 기록 동기화나 온라인 백업을 의미하지 않습니다. |
| 외부 요청 | 운영 웹에서는 중앙 공통 계정 JS/CSS와 계정 상태 확인 요청이 생깁니다. 개인 기록·한눈애 초대 fragment는 인증 요청에 자동으로 포함하지 않습니다. |
| 장애·오프라인 | 공통 계정 로딩과 개인 기록 기능을 분리합니다. 중앙 모듈을 불러오지 못하면 외부 한눈 계정 웹사이트 링크를 유지합니다. 원격 계정 모듈은 오프라인 캐시에 넣지 않습니다. |
| Android·미리보기 | `appassets.androidplatform.net`, `file:`, 로컬 미리보기에서는 중앙 계정 모듈을 로드하지 않고 외부 계정 웹사이트 링크를 제공합니다. Android 번들은 자체 앱 업데이트로 갱신하므로 PWA 서비스워커도 설치하지 않습니다. |
| 광고 | 웹 AdFit 요청·운영 광고 ID·승인 없는 광고 지면을 넣지 않았습니다. `AdMobNative/1` 환경을 식별하여 웹 광고 비활성 정책을 유지합니다. 실제 네이티브 AdMob·UMP는 Android 공통 라이브러리가 처리합니다. |
| 데이터 이동 | 주소·기기·브라우저·WebView 간 자동 동기화가 없습니다. JSON 파일로 백업·복원합니다. |

계정 폴백 주소는 `https://softm-hannun-account.softm.workers.dev/account`이며 새 창에서 엽니다. 공통 계정 연결은 현재 등록된 운영 origin `https://softm.github.io`에서만 초기화합니다. 다른 도메인에 배포한다면 중앙 사이트 origin 등록과 `common-account.js`의 허용 호스트를 함께 변경해야 합니다.

### Android 연결

`native-bridge.js`는 신뢰하는 앱 asset-loader origin에서만 `HannunNative.postMessage`를 사용합니다. 메시지는 `downloadText`(텍스트 파일 저장), `share`(사용자가 누른 링크 공유), `print`(인쇄) 세 종류입니다. 일반 브라우저에서는 기존 다운로드·시스템 공유·인쇄 동작을 사용합니다. 네이티브 저장 결과는 `hannun-native-result` 이벤트로 반영하고, 파일 선택 입력은 Android의 문서 선택 창에 연결합니다.

한눈애 초대·비교 링크는 일반 웹에서는 현재 URL의 origin과 pathname을 보존합니다. Android 번들·`file:`에서는 공유 대상이 실제로 열 수 있도록 `https://softm.github.io/hannunae-web/`를 사용합니다. 답변은 계속 `#invite=` / `#compare=` fragment에만 넣습니다.
